# ML methodology

How SentinelAI's flow classifier is built and evaluated, and what the results
do and do not show. Code: [`ml/`](../ml/README.md). Full generated report with
plots: [`ml/reports/2026.10.03/report.md`](../ml/reports/2026.10.03/report.md).

## 1. Problem

Classify each network flow (a bidirectional 5-tuple conversation) as benign
or one of six attack classes, with a confidence and an explanation, fast
enough to run on live traffic. The output feeds the risk engine and the
alert engine (see [`API.md`](API.md#detection-stream-ml-engine--alert-engine)).

## 2. Data

CIC-IDS2017 (`MachineLearningCVE`, 8 CSVs, 2,830,743 flows, generated by
CICFlowMeter from a week of lab traffic). Labels are mapped to:

| SentinelAI class | CIC labels |
|---|---|
| benign | BENIGN |
| ddos | DDoS (LOIC) |
| dos | DoS Hulk, GoldenEye, slowloris, Slowhttptest |
| portscan | PortScan |
| bruteforce | FTP-Patator, SSH-Patator |
| webattack | Web Attack – Brute Force, XSS, SQL Injection |
| botnet | Bot (Ares) |

Infiltration (36 flows) and Heartbleed (11) are dropped: too few to learn or
to evaluate.

**Cleaning** (counts from the 2026.10.03 run): 115 flows with negative
duration (a CICFlowMeter bug) removed; **653,453 exact duplicates** removed;
810 flows whose identical feature vectors carry different labels removed;
2,176,318 flows kept. Deduplication matters: without it, copies of the same
flow sit on both sides of the split and inflate the scores.

## 3. Features

37 per-flow statistics, defined once in `sentinel_ml/features.py` and used by
both training and live inference: duration, packet and byte counts per
direction, packet-length statistics, inter-arrival-time statistics, TCP flag
counts, initial TCP window sizes, active/idle times. Units are normalised
(seconds, bytes).

Deliberate choices:

- **Only features the live flow builder can compute.** The previous prototype
  trained on NSL-KDD fields that cannot be derived from packets, so live
  predictions did not match training. A test checks that a flow given as a
  live record and as a CSV row produces an identical vector and prediction.
- **Rates are recomputed** from totals and duration (zero duration gives 0),
  instead of CICFlowMeter's columns, which contain Infinity/NaN.
- **No ports, IPs or timestamps.** Identifiers let a model memorise the
  testbed ("port 80 = attack") instead of learning behaviour.
- **Preprocessing travels with the model.** A signed log transform (for heavy
  tails) is the first step of every saved Pipeline, so training and inference
  cannot drift apart. No separate scaler file exists to get out of sync.

## 4. Split and validation

- **Temporal split per attack run**: within each (file, original label) group,
  the first 70% of flows (capture order) train, the last 30% test. A random row
  split would put near-identical consecutive flows of one attack on both sides.
- **Blocked 5-fold cross-validation** on the training part only (contiguous
  chunks per group), used to choose the model.
- The test set (652,904 flows, real class mix, ~85% benign) is used once, to
  report every candidate.
- Training is capped at 150,000 flows per class (385,233 used) to bound
  training time; rare classes keep all their flows. Class imbalance is handled
  with balanced class weights (`class_weight` or balanced sample weights for
  XGBoost), not oversampling.

## 5. Models and results

| Model | CV macro-F1 | Test macro-F1 | Accuracy | ROC-AUC | Attack detection | False positives | Latency |
|---|---:|---:|---:|---:|---:|---:|---:|
| Logistic regression (baseline) | 0.884 | 0.463 | 85.75% | 0.990 | 96.90% | 15.22% | 0.7 ms |
| Random forest | 0.979 | 0.769 | 98.95% | 0.994 | 98.36% | 0.69% | 37 ms |
| **XGBoost (selected)** | **0.985** | **0.828** | **99.48%** | **0.9995** | **99.27%** | **0.20%** | **1.2 ms** |

*Attack detection*: attack flows flagged as any attack. *False positives*:
benign flows flagged as an attack. Latency: one flow on its own, 4-core VM.

Per class (XGBoost, test set):

| Class | Precision | Recall | F1 | Test flows |
|---|---:|---:|---:|---:|
| benign | 0.999 | 0.998 | 0.998 | 552,084 |
| ddos | 1.000 | 0.999 | 0.999 | 38,404 |
| dos | 0.993 | 0.963 | 0.978 | 58,050 |
| bruteforce | 0.998 | 0.995 | 0.996 | 2,745 |
| webattack | 0.792 | 0.974 | 0.873 | 644 |
| botnet | 0.416 | 0.924 | 0.573 | 421 |
| portscan | 0.238 | 0.880 | 0.374 | 556 |

**Reading the results**

- Volumetric and connection-based attacks (DDoS, DoS, brute force) are
  separated almost perfectly, with a 0.2% false-positive rate on benign flows.
- **Port scans and botnet traffic are the weak spot.** Deduplication shrank
  158,930 port-scan flows to 1,851 distinct ones: individual scan probes are
  feature-identical to each other and close to short benign flows. Recall is
  high, but precision is low because a small share of 552,084 benign flows
  outnumbers 556 scan flows. A scan is a pattern *across* flows (one source,
  many ports), so the fix is window-level features (distinct destination
  ports/hosts per source, flows per second per destination), planned for the
  real-time engine, rather than more per-flow tuning. The engine now adds an
  explicit rule on top of the classifier: one source reaching 20+ distinct
  ports on a host within 10 s raises a `portscan` detection
  (`model_version: rule:portscan-v1`), explained by the port count.
- **CV vs test gap** (0.985 vs 0.828 macro-F1): CV runs on class-capped data,
  the test set on the real mix, which punishes precision on rare classes. The
  test numbers are the realistic ones.
- **XGBoost was chosen** for the best CV score, and it is also the most precise
  on the test set and ~30× faster per flow than the random forest.

## 6. Explainability

Every attack prediction carries its top-5 SHAP contributions towards the
predicted class, with each feature's share of the total attribution:

```
DDoS -> ddos detected — confidence 100.0%
   bwd_bytes            ███████       31.8%
   init_win_bytes_bwd   █████         22.0%
   bwd_pkt_len_mean     █              7.4%
```

Global importance (mean |SHAP|, test sample) is led by the initial TCP window
sizes, then inter-arrival-time statistics and packet sizes.

## 7. Threats to validity

- **Single dataset.** All numbers come from one lab capture; there is no
  cross-dataset evaluation yet (UNSW-NB15 or CIC-DDoS2019 would be next). Expect
  lower scores on other networks until the model is validated on live traffic.
- **Shortcut risk in TCP window sizes.** They rank highest and partly reflect
  the testbed's operating systems. An ablation without them is a planned check.
- **Known dataset errors.** CIC-IDS2017 has documented flow-construction and
  labelling problems (Engelen et al., 2021); the corrected re-release is a
  candidate for future training.
- **Feature parity with CICFlowMeter.** The Phase 5 Scapy flow builder must
  reproduce CICFlowMeter's definitions; it will be validated against
  CICFlowMeter output on a sample capture.
- **Adversarial robustness** is not evaluated: crafted traffic can evade
  flow-statistics models.
- SHAP explains the model's reasoning, not ground-truth causality.

## 8. Reproducing

```bash
# CSVs in data/raw/cic-ids2017/MachineLearningCVE/ (data/README.md)
pip install -r ml/requirements.txt
PYTHONPATH=ml python -m sentinel_ml train     # ~6 min on 4 cores, seed 42
```

The run writes the bundle to `models/sentinel-flow/<version>/` and the report
to `ml/reports/<version>/`. The dataset digest, cleaning counts, parameters,
library versions and git commit are recorded in `model_metadata.json`.
